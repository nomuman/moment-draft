# 読込検証

この記録は読込段階の検証。[後続の編集・書き出しの検証](editor-validation.md)を別に記録する。

## 今回の問い

PCブラウザでローカルの写真と動画を混在して読み込み、縦素材を切り取らずに表示し、確認用画像を抽出できるか。

`experiments/intake.html` はこの問いのための使い捨てコード。製品のUI・フレームワーク・処理場所を確定するものではない。

## 現在の対象

本人の指定により、動画を含む別の共有アルバムへ切り替えた。共有画面の情報は1,879点。全件は取得せず、写真2枚・動画2本を最初の検証対象に選んだ。
選んだ4点の原本を取得した。合計5,637,883,661 bytes。横動画1本が5,627,164,525 bytesを占める。共有画面で約6分36秒と表示された動画の、ファイル上の長さは396.821333秒だった。

写真2枚からのJPEG抽出と、動画2本の再生・一時停止・前送り後のJPEG抽出を確認した。4Kの横動画では392.85秒の位置から960×540のJPEGを抽出できた。

| 横動画 | MP4内のHEVC、10bit | 3840×2160 | 396.821333秒 | AACステレオ、48kHz |

個別のファイル名・映像・音声・共有URL・位置情報は公開対象に含めず、ローカルの `.local/events/event-002/` に記録する。

- 写真2点と動画の0.40秒の位置からJPEGを抽出できた。縦写真は余白を保って表示された。

音声を持つ合成WebMの再生コントロールと消音されていない設定を確認した。人が実際に聞いた音質の検証ではない。

## 記録の意味

- `selectionToMetadataMs` はファイル選択イベントから、全ファイルの読込成功・失敗の確認まで。動画全体のデコード、アップロード、Jev判定、初案作成を含まない。
- `metadataMs` は1ファイルの画像読込または動画メタデータ確認まで。
- `extractedFrames` は抽出した位置・表示寸法・JPEG容量・抽出処理時間。動画全体や場面の評価ではない。
- `synthetic: null` は素材の由来をページが判定できないことを示す。合成検証の記録では明示的に `true` を付ける。
- `initialDraftMs: null` と `cost: null` は未測定。ゼロ円や目標達成を意味しない。

動画の表示寸法・時間はブラウザのメタデータに依存する。コーデック・EXIFの詳細・HDR・音声トラックの解析は行わない。
確認用JPEGの長辺960px・品質0.85はこの実験の便宜的な設定で、Jev用画像の仕様ではない。

## 未検証

今回と異なる形式・端末、HEIC、HDRやMPOの色再現、可変fps、全写真の原本との色・向きの照合、全編視聴と音の聞こえ方、対象ブラウザ間の差は未検証。
Jevとの比較、約60秒の初案、カード編集、BGM、完成動画の書き出し、本人の手直し時間・満足・原価は未検証。

手元のPATH上の既存FFmpeg 7.1はx86_64版で、`Bad CPU type in executable` により起動しなかった。
検証用の `.local/media-runtime/` へPyPIの `imageio-ffmpeg` と `av` を導入し、ARM版FFmpeg 7.1の起動とPyAV 18.1.0による実動画の先頭映像・音声のデコードを確認した。実行ファイルは再配布せず、製品の実行基盤の採用決定とは分ける。
