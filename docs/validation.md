# 読込検証

## 今回の問い

PCブラウザでローカルの写真と動画を混在して読み込み、縦素材を切り取らずに表示し、確認用画像を抽出できるか。

`experiments/intake.html` はこの問いのための使い捨てコード。製品のUI・フレームワーク・処理場所を確定するものではない。

## 対象

本人の1イベント分の素材フォルダは未提供。実素材の形式・枚数・時間・容量は未確認。
最初の動作確認には、その場で生成した合成JPEG・PNG・音声付きWebMと、意図的に壊したファイルを使う。
壊したHEICの失敗を、有効なHEICの非対応を示す証拠として扱わない。

## 合成素材で確認したこと

2026-10-18、手元のChrome 155.0.8059.80を自動操作して確認した。

- 横写真JPEG・縦写真PNG・音声付きWebMの3点を読み込み、寸法と動画時間を取得できた。
- 写真2点と動画の0.40秒の位置からJPEGを抽出できた。縦写真は余白を保って表示された。
- 壊れた画像と種類不明ファイルの2点を失敗として残し、個別に説明を表示した。
- JSON保存、素材の解除、読込中の解除・再選択、101点の拒否が動作した。
- 1280px幅と390px幅で表示を確認した。390px幅で横にはみ出さなかった。
- 操作中の外部HTTPリクエスト・ページのJavaScript例外は発生しなかった。

音声を持つ合成WebMの再生コントロールと消音されていない設定を確認した。人が実際に聞いた音質の検証ではない。
これらは小さな合成素材の動作確認であり、実素材100点での処理性能や対応形式を保証しない。
記録とスクリーンショットはローカルの `.local/` に置き、公開対象から除外する。

## 記録の意味

- `selectionToMetadataMs` はファイル選択イベントから、全ファイルの読込成功・失敗の確認まで。動画全体のデコード、アップロード、Jev判定、初案作成を含まない。
- `metadataMs` は1ファイルの画像読込または動画メタデータ確認まで。
- `extractedFrames` は抽出した位置・表示寸法・JPEG容量・抽出処理時間。動画全体や場面の評価ではない。
- `synthetic: null` は素材の由来をページが判定できないことを示す。合成検証の記録では明示的に `true` を付ける。
- `initialDraftMs: null` と `cost: null` は未測定。ゼロ円や目標達成を意味しない。

動画の表示寸法・時間はブラウザのメタデータに依存する。コーデック・EXIFの詳細・HDR・音声トラックの解析は行わない。
確認用JPEGの長辺960px・品質0.85はこの実験の便宜的な設定で、Jev用画像の仕様ではない。

## 未検証

実素材のHEIC・HEVC・MOV・HDR・可変fps、原本との色・向きの一致、音の聞こえ方、対象ブラウザ間の差は未検証。
Jevとの比較、約60秒の初案、カード編集、BGM、完成動画の書き出し、本人の手直し時間・満足・原価は未検証。

手元の既存FFmpeg 7.1の実行ファイルは `Bad CPU type in executable` で起動しなかった。
native FFmpeg自体が利用できないという結論ではない。書き出し検証前に、このPCに適した実行環境を別途用意する必要がある。

## 次の検証

1. 本人の1イベント分のフォルダを指定し、合計点数・容量・動画時間と失敗を記録する。
2. 向き・色・音と抽出画像を原本と見比べる。
3. 単純な選別を作り、本人が残したかった場面との差を記録する。
4. Jevへの送信条件・費用を確認したうえで、同じ候補との比較へ進む。

APIキー、顔・場所を含む実素材、個人のファイル名、ローカル検証結果を公開リポジトリへ追加しない。
