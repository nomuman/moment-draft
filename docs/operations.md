# ローカル運用と公開前の確認

この文書は、本人のPCで試す単一ホストのサービスを扱う。`compose.yaml` はホストの `127.0.0.1:8770` にだけポートを公開する。外部公開、契約、決済、実素材の送信はこの手順に含まれない。

## ローカルコンテナを起動する

Docker Engine と Compose が使える環境で、リポジトリのルートから実行する。

```sh
docker compose build
docker compose run --rm --no-deps moment-draft python scripts/release_check.py --mode local
docker compose up --no-build
```

事前確認の全項目が `PASS` なら、ブラウザで `http://127.0.0.1:8770` を開く。`GET /healthz` は個人データを返さない。停止時は `docker compose down` を実行する。名前付きボリューム `moment-data` は停止後も残る。ボリュームの削除はこの手順に含めない。

コンテナは非rootのユーザーで動き、アプリ用のデータだけを `/data` に保存する。ルートファイルシステムは読み取り専用で、一時ファイルは上限付きの `/tmp` を使う。CPU、メモリ、プロセス数にも上限を設定している。これらは試用用の設定値であり、100点の素材や同時利用に必要な容量を測定した結果ではない。

`MOMENT_CONTAINER_LOCAL=1` は、コンテナ内で `0.0.0.0` を待ち受けつつ、ホストではループバックだけに公開するための例外である。`compose.yaml` の `127.0.0.1:8770:8770` を外部公開アドレスに変更すると、この保護は成立しない。設定変更後は起動前に公開範囲を再確認する。

## ホスト上で事前確認する

Python 3.11、FFmpeg、`requirements.txt` の依存パッケージを用意する。データディレクトリは実行ユーザーが所有し、権限を `0700` にする。事前確認は設定とファイルシステムを読むだけで、ディレクトリの作成や削除はしない。

```sh
install -d -m 700 "$PWD/.local/data"
MOMENT_DATA_DIR="$PWD/.local/data" python scripts/release_check.py --mode local
```

スクリプトはオリジンと待受先、保持日数、FFmpeg に指定したパスの実行可能性、データディレクトリの所有者と権限、空き容量10 GiBを確認する。`PASS` はその時点の設定確認を意味する。FFmpeg の機能、素材の読み込み、書き出し、再起動後の復元、利用者間の隔離を証明しない。終了コードは全項目合格で `0`、失敗項目があれば `1`、人による現地確認が残る場合は `2` である。結果にアクセスコードの値は出さない。

## 公開を検討する前に決める

公開用の `--mode public` は HTTPS オリジン、公開用の待受先、アクセスコードの設定を調べる。TLS 終端、信頼するプロキシ、Secure Cookie、外部からの入場制御、実機の動作は `PENDING` と表示する。このスクリプトだけで公開可とは判定しない。ローカルコンテナの設定をそのまま公開に転用しない。

公開前に次を決め、対象ホストで検証する。

1. ドメイン、TLS 終端、プロキシからアプリへ渡す Host と Origin、およびアクセスコードの配布方法を決める。秘密値をリポジトリに保存しない。
2. 利用者ごとの閲覧とダウンロード拒否、CSRF、アップロード上限、再起動後の復元、ジョブ中断と再試行を実際の経路で確認する。
3. 7日保存の起点、期限延長の有無、期限切れデータのアクセス拒否と物理削除の手順を決める。削除対象はサービスが所有する複製だけに限定し、削除前に dry run の対象一覧を確認する。
4. 実素材を扱う運用者、保存先、バックアップ、障害時の連絡、アクセスログに残す情報を決める。ログにファイル名、Cookie、アクセスコード、素材本文を記録しない。
5. 実素材でブラウザの操作感、書き出し品質、手直しに要する時間を確認する。合成素材のCIは、この体験を証明しない。

公開先の選定、外部サービス契約、デプロイ、実素材の送信には別の判断と承認が必要である。

## 原価を実測する

予算の判断には、同じテストセットで入力総量、アップロード量、書き出し量、保存した日数、再編集回数、CPU時間、ピークメモリ、ダウンロード転送量を記録する。候補先の最新料金と無料枠を確認し、計測値を当てはめる。待機時の費用、失敗した再試行、バックアップ、転送料も含める。現時点ではプロバイダーと実測値がないため、金額の見積もりは示さない。
